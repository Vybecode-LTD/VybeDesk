01 · Principles

What the system optimizes for

A quick, opinionated north star before the tokens. Designers and engineers should be able to make calls without checking back.

P1

Quiet by default

Nothing competes for attention unless it must. Color is a tool, not a decoration. Surfaces stay flat; depth comes from elevation, not gradients.

P2

Read like a tool

Mono for identifiers, status, data, paths, durations. Sans for prose. Numbers are tabular. Type is sized for hours, not for screenshots.

P3

Honest motion

Motion describes structure: where something came from, where it's going. Never decorative, never longer than 320ms, almost always under 200.

02 · Color

Tokens, not values

Every color is named for its role. Use roles in components — never raw values. Both themes share the same token graph.

07 · Implementation notes

Mapping to Avalonia

Quick pointers so this isn't just a web mock. Everything here is implementable with stock Avalonia 11.

Tokens → Resources

App.axaml

All CSS variables map 1:1 to ResourceDictionary entries. Define one dictionary per theme (StratumLight.axaml / StratumDark.axaml) and swap via RequestedThemeVariant. Density becomes a DynamicResource set you swap at runtime.

Components → ControlTheme

Styles

Each component on this page corresponds to a single ControlTheme targeting Button, TextBox, ComboBox, CheckBox, TabControl, DataGrid, etc. Hover / focus / disabled states use Avalonia visual-state selectors (:pointerover, :focus-visible, :disabled).

Type pipeline

Fonts

Ship Geist + Geist Mono as avares:// font assets. Set FontFamily on the root Window; everything inherits. For tabular numbers, set FontFeature to tnum on data controls.

Motion

Transitions

Use Transitions on color, opacity, and transform properties — never on layout. Four durations (80 / 140 / 200 / 320ms) cover every state change. Indeterminate progress uses DoubleAnimation with RepeatBehavior=Forever.
